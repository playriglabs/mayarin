---
title: React pay button
description: Send a buyer to the hosted checkout from any React app, with no product catalog on the dashboard.
---

```tsx
import { PayButton } from "@mayarin/react";

<PayButton checkout={() => fetch("/api/pay", { method: "POST" }).then((r) => r.json())}>
  Pay with crypto
</PayButton>;
```

`@mayarin/react` is one button and one hook. A click mints a payment intent, then sends the buyer to the hosted checkout, which handles asset choice, the wallet or deposit address, and live status. You do not create products or payment links on the dashboard first: the amount comes with the click.

## Two modes, and who decides the price

| Mode    | Props                                   | Who sets the amount | Use it for                          |
| ------- | --------------------------------------- | ------------------- | ----------------------------------- |
| Server  | `checkout`                              | Your backend        | Anything you sell                   |
| Browser | `publishableKey`, `baseUrl`, `amount`, `currency` | The browser         | Donations, tips, pay-what-you-want  |

**Server mode** calls your backend. Your backend mints the intent with its secret key and returns the URL. The price never leaves your server, so nobody can change it.

```ts
// Your backend — e.g. POST /api/pay
import { createMayarin } from "@mayarin/sdk";

const mayarin = createMayarin({
  baseUrl: "https://api.mayarin.xyz",
  secretKey: process.env.MAYARIN_SECRET_KEY!,
});

const { url } = await mayarin.commerce.carts.checkout({
  currency: "IDR",
  lines: [{ name: "Order #123", unitPrice: { amount: "150000.00", asset: "IDR" }, quantity: 1 }],
  merchantReference: "order_123",
  metadata: { checkoutSuccessBaseUrl: "https://shop.example/thanks" },
});

return Response.json({ url });
```

`checkout` may resolve to the URL string or to any object with a `url` field.

**Browser mode** needs no backend. The browser mints the intent itself with a [publishable key](/guides/authentication):

```tsx
<PayButton
  publishableKey="pk_…"
  baseUrl="https://api.mayarin.xyz"
  amount="150000.00"
  currency="IDR"
  name="Support the shop"
  merchantReference="donation_42"
  successUrl="https://shop.example/thanks"
>
  Pay with crypto
</PayButton>
```

> **Warning:** in browser mode the amount is whatever the browser sends, and a buyer with devtools can change it. Before you ship goods paid this way, check the paid amount against your own order in the [webhook](/sdk/typescript/webhooks), matched by `merchantReference`. For a fixed-price sale, use server mode.

What the browser cannot change: the merchant. A publishable key names its merchant, and the checkout page always shows that merchant's own name, city and country from the dashboard settings. Set your city and country first, or the API refuses the checkout.

## Props

| Prop                | Mode    | Meaning                                                                                   |
| ------------------- | ------- | ----------------------------------------------------------------------------------------- |
| `checkout`          | Server  | `() => Promise<string \| { url: string }>`                                                 |
| `publishableKey`    | Browser | A `pk_…` key. No merchant id needed.                                                       |
| `baseUrl`           | Browser | The payment API origin for your environment.                                               |
| `amount`            | Browser | Decimal string per unit, e.g. `"150000.00"`. Never a number.                               |
| `currency`          | Browser | The currency you price in, e.g. `"IDR"`.                                                   |
| `name`              | Browser | The line the buyer sees. Default `"Payment"`.                                              |
| `quantity`          | Browser | Default `1`.                                                                               |
| `merchantReference` | Browser | Your order id. Returned on the payment and in every webhook.                               |
| `successUrl`        | Browser | After paying, the buyer lands on `{successUrl}/{paymentIntentId}`. HTTPS or localhost.     |
| `metadata`          | Browser | String key/value pairs stored on the intent.                                               |
| `onRedirect`        | Both    | `(url) => void`. Handle navigation yourself, e.g. open a new tab. Default: same tab.        |
| `onError`           | Both    | `(error) => void`. The button stays clickable after an error.                              |
| `children`          | Both    | Any React node, or `({ loading }) => node`. Default `"Pay with crypto"`.                   |

Every other prop (`className`, `style`, `id`, `disabled`, `aria-*`) is passed to the `<button>` unchanged. The button has no styling of its own, and it never submits a surrounding form.

## Custom content and busy state

```tsx
<PayButton checkout={createCheckout} className="btn-primary">
  {({ loading }) => (loading ? <Spinner /> : <><CryptoIcon /> Continue</>)}
</PayButton>
```

While the intent is being minted the button is `disabled` with `aria-busy="true"`. A second click does nothing.

## Headless: `useMayarinCheckout`

Use the hook when the trigger is not a plain button, such as a design-system component or a form submit:

```tsx
import { useMayarinCheckout } from "@mayarin/react";

const { redirect, loading, error } = useMayarinCheckout({ checkout: createCheckout });

<Button onClick={redirect} loading={loading}>Pay</Button>;
{error && <p role="alert">{error.message}</p>}
```

It takes the same options as `PayButton`. They are read when `redirect` runs, so a cart total that changes after the first render is always the current one.

The [demo storefront](https://github.com/playriglabs/mayarin/tree/main/apps/demo) uses the hook in server mode on its shipping step.
